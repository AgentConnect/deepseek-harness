# Agent Note: 在不关闭应用的情况下恢复受控 Electron Host

Status: implemented

[English](2026-08-20-recover-owned-electron-host.md) | 中文

## Problem

Electron 主进程把受控 `dsh web` 子进程的每次意外退出都当作应用级致命事件。它同步显示错误框后调用 `app.quit()`，因此即使新的本地 Host 能够使用相同状态重新启动，用户确认错误也会关闭所有窗口。就绪期间保留的输出随后会被丢弃，Host 就绪后崩溃时也没有有界诊断信息。

## Decision

活动 Host 退出时，Electron 壳层保留现有窗口。它用无脚本的本地恢复状态替换已不可用的回环页面，并采用滚动窗口重启策略：一分钟内最多自动尝试两次，延迟分别为 300 毫秒和一秒。替代进程成功启动后会成为唯一活动的受控 Host，窗口加载它新校验通过的回环来源。

自动重试额度耗尽后，原生对话框会明确提供重新启动 Host、复制诊断信息或退出应用三种操作。手动重启失败后返回相同选择，不会退出，也不会进入自动循环。进程包装层会在完整生命周期内保留合并 stdout 与 stderr 的 16 KiB 尾部，在转发或保留输出前移除形似凭据的请求头、赋值、Bearer 值和 URL 参数，而且不会把诊断信息发送给 Host 渲染器。

应用正常关闭与崩溃恢复保持分离。正常关闭会停止后续恢复，请求当前受控子进程停止，等待进程完全停稳，然后才完成 Electron 退出。

## Alternatives considered

**保留错误框并在其后无条件退出。** 予以否决，因为本地子进程失败不等于 Electron 应用或其持久状态不可用，而且确认按钮看似提供恢复机会，实际上只是延迟强制退出。

**使用固定延迟无限重启。** 予以否决，因为确定性的启动故障会造成无界子进程循环，并对用户隐藏问题。滚动额度既能恢复瞬态故障，也能保留明确的终止选择。

**在 Web 应用中渲染原始子进程输出。** 予以否决，因为不可用的 Host 无法负责自己的故障 UI，而且原始输出可能包含凭据。Electron 所有者只保留有界、脱敏的尾部，并仅通过用户明确选择的原生复制操作暴露。

## Consequences

瞬态 Host 崩溃不再破坏桌面会话，也不再迫使用户重新打开应用。重复崩溃保持有界、可观察且由用户控制，普通退出仍能避免留下孤儿 Host 进程。

恢复页面有意保持为最小本地页面；替代 Host 就绪前，它无法提供正常 DSH 功能。脱敏覆盖常见凭据形态而不是任意秘密，因此应用日志本身仍不得写入敏感值。
